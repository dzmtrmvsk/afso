# Adaptive Field Service Orchestrator (AFSO)

**SaaS платформа для управления выездными бригадами и внутренних сервисных процессов с автоматическим назначением, SLA-контролем, очередями и аналитикой.**

## Обзор

AFSO — это корпоративная платформа управления выездными сервисами, которая автоматически распределяет рабочие заявки между выездными агентами и обеспечивает своевременное выполнение. Система заменяет ручной процесс "кто свободен — тому и отдали" на интеллектуальное распределение на основе очередей, бизнес-правил и SLA-таймеров.

### Целевой рынок

- Компании с выездными сервисами (IT-аутсорс, ремонт, HVAC, мобильная медицина)
- Логистика и доставка
- Управление объектами и имуществом
- Любые организации с выездной рабочей силой

### Ценностное предложение

- **Снижение времени отклика**: Автоматическое назначение исключает задержки координации
- **Соответствие SLA**: Встроенные таймеры и эскалация предотвращают нарушения
- **Экономия затрат**: Требуется меньше сотрудников для диспетчеризации и координации
- **Качество обслуживания**: Видимость в реальном времени и автоматизированные рабочие процессы
- **Модель доходов**: Подписка SaaS ($15/пользователь/месяц или $99/месяц для команд до 10 человек)

### Ключевые отличия

В отличие от традиционных трекеров задач, AFSO предоставляет:
- **Активная оркестровка**: Задачи живут в интеллектуальных очередях, а не просто хранятся
- **Автономное принятие решений**: Система автоматически назначает на основе нагрузки и навыков
- **Обеспечение SLA**: Таймеры, эскалации и автоматическое переназначение
- **Событийная архитектура**: Полный журнал аудита и обновления в реальном времени

## Техническая архитектура

### Обзор стека

**Монолитная архитектура** с модульной структурой в одном репозитории.

#### Backend (`server/`)
- **NestJS**: RESTful API, фоновые рабочие процессы, cron-задачи
- **PostgreSQL**: Основная реляционная база данных (пользователи, организации, заявки, назначения, SLA-политики, счета)
- **MongoDB**: Event store, история изменений, неструктурированные логи (быстрое добавление/чтение)
- **Redis**: Кеширование, сессии, ограничение частоты запросов, счетчики в реальном времени
- **BullMQ**: Очереди задач для автоназначения, SLA-таймеров, эскалаций, интеграций

#### Frontend (`client/`)
- **React**: Фреймворк UI
- **Material-UI (MUI)**: Библиотека компонентов
- **SCSS**: Стилизация
- **Socket.IO**: Обновления в реальном времени через WebSocket
- **Optimistic UI**: Немедленная обратная связь для действий пользователя

### Точки технической сложности

- Управление очередями задач с BullMQ
- Отложенные/запланированные задачи (SLA-таймеры)
- Многоуровневая стратегия кеширования
- Event sourcing и логирование аудита
- Масштабируемая архитектура очередей
- Двусторонняя коммуникация в реальном времени

- Интеллектуальное распределение очередей
- Автоматическое назначение на основе навыков и нагрузки
- Ручное переопределение назначения
- Балансировка нагрузки (порог разницы <=10%)

### 5. SLA и эскалация
- Конфигурация SLA-политик
- Автоматическое инициирование таймера
- Обнаружение нарушений и эскалация

### 6. Уведомления и интеграции
- Email-уведомления
- Интеграция с Telegram

## Инструкции по установке

### Предварительные требования
- Node.js 24+
- PostgreSQL 17+
- MongoDB 6+
- Redis 7+
- Docker

### Установка бэкенда
```bash
cd server
npm install
cp .env.example .env
# Настройте подключения к базам данных в .env
npm run migration:run
npm run dev
```

### Установка фронтенда
```bash
cd client
npm install
cp .env.example .env
# Настройте конечную точку API в .env
npm run dev
```

### Установка с Docker
```bash
docker-compose up -d
```

## Стратегия тестирования

- **Модульные тесты**: Jest для бизнес-логики
- **Интеграционные тесты**: Тестирование взаимодействия с базой данных
- **E2E тесты**: Тестирование полных пользовательских рабочих процессов
- **Нагрузочные тесты**: Проверка производительности очередей под нагрузкой
